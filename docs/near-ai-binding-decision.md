# NEAR AI transcript and plaintext verification

PactPay uses `@nearai/inference-sdk` version 0.3.0 with E2EE enabled. The provider TEE signature authenticates the exact encrypted request and response bytes. The application decrypts these bytes before displaying its local analysis, and it computes the input and output hashes locally. The agreement commits to these local hashes together with the transcript. A recipient can verify this commitment and the provider signature, while the exported proof contains no mechanism for independently obtaining both plaintexts from the signed encrypted bytes. [NEAR AI verification guide](https://github.com/nearai/inference-sdk/blob/main/js/docs/verification-guide.md)

The SDK preparation API returns a decryptor for its own response. The model's private key remains inside the attested service and the PactPay export has no supported opening for the request. The signed transcript and plaintext binding therefore retain separate states. The plaintext check stays **Unavailable** when a transcript verifies. Publishing the original plaintext request or replacing a model signature with a PactPay server signature would change the privacy or trust properties.

The hosted synthetic Testnet check returned completion `730116a4890643008da92246c068f9fb` with `encrypted-transcript-verified` and plaintext `unavailable`. A future provider contract must authenticate both plaintext digests with the same completion identity and settlement scope, or supply independently verifiable openings for the same signed ciphertext. A portable verifier would need fixtures for altered input, output, scope, nonce, canonicalization version and absent openings before the plaintext status can be promoted.
